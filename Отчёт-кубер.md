# Отчёт: Развёртывание MentorFlow в Kubernetes (Production-Ready)

## 1. Архитектура и объекты Kubernetes

В кластере Minikube развёрнуты следующие ресурсы (оркестрация через `k8s/kustomization.yaml`):

* **Namespace (`mentorflow`)**: все ресурсы приложения, базы данных и кэша изолированы от системных компонентов и `default`-неймспейса.
* **StatefulSet + PVC (`postgres-statefulset` и `redis-statefulset`)**: используются для обоих stateful-компонентов. PostgreSQL (`1Gi`) и Redis (`512Mi` с включённым AOF `--appendonly yes`) используют `volumeClaimTemplates`, что гарантирует сохранение состояния на постоянных томах (`PersistentVolumeClaim`) при перезапуске подов.
* **Job (`mentorflow-migration`)**: миграции схемы БД (Flyway) вынесены из старта веб-приложения в отдельную Kubernetes `Job` (`args: ["--migrate"]`) с `initContainer` ожидания готовности PostgreSQL. Само веб-приложение запускается с `SPRING_FLYWAY_ENABLED=false` только после успешного завершения миграций.
* **Deployment (`mentorflow-app`)**: управляет stateless-репликами бэкенда с поддержкой плавного завершения (`terminationGracePeriodSeconds: 30` + `preStop` хук) и автоскейлингом.
* **Probes (`startupProbe`, `readinessProbe`, `livenessProbe`)**: настроены для каждого компонента:
    * `postgres` — проверка готовности сокета через `pg_isready`;
    * `redis` — проверка ответа через `redis-cli ping`;
    * `mentorflow-app` — раздельные HTTP-пробы Spring Boot Actuator (`/actuator/health/liveness` и `/actuator/health/readiness`).
* **Resources (`requests` / `limits`)**: заданы для всех контейнеров.
* **Service (`ClusterIP` и `NodePort`)**: внутренние сервисы `postgres-service:5432` и `redis-service:6379` (`ClusterIP`), внешний доступ к UI приложения через `mentorflow-service` (`NodePort: 30080`).
* **ConfigMap и Secret**: `mentorflow-config` и `mentorflow-secret` хранят нечувствительные настройки и учётные данные.

## 2. Масштабирование и планирование 

* **HorizontalPodAutoscaler (`mentorflow-app-hpa`)**: настроен на автоматическое горизонтальное масштабирование `Deployment` от 1 до 3 реплик при превышении средней загрузки CPU порога в 70%
